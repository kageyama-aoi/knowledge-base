## 第1章：JSDocとは何か（概念）

### JSDocは「設計メタデータ」

JSDocは単なるコメントではなく、**設計情報そのもの**。最初から以下の情報が含まれている。

- クラス・関数名
- 引数（名前・型・意味）
- 戻り値
- 責務（description）
- 依存関係（型参照）

これらはそのまま HTMLドキュメント・クラス図（Mermaid）・設計レビュー・AI入力用メタデータに変換できる。

### GASでも使えるか？

**完全に使える。しかも価値は同じ。**

JSDocは実行に影響しない。JavaScriptの実行環境にも依存しない。IDE・ツール・AIが読む情報として機能する。

| 観点 | Webアプリ | GAS |
|------|---------|-----|
| JSDocが書ける | ○ | ○ |
| 補完・設計理解 | ○ | ◎ |
| 引き継ぎ資料代わり | △ | ◎ |

## 第2章：GAS向け JSDoc コメント作法（実務ガイド）

> **目的**: GASのコードに「意味が残るコメント」を最小コストで書く。
> 文法暗記ではなく、**使いどころが分かること**をゴールにする。

### まず覚えるべき5つ

| タグ | 何のため | 主な使いどころ |
|------|---------|--------------|
| `@param` | 関数の入口を説明 | 関数定義 |
| `@return` | 関数の出口を説明 | 関数定義 |
| `@typedef` | オブジェクト構造の設計図 | 設定・データ構造 |
| `@type` | 変数・定数の型 | 定数・共有変数 |
| `@fileoverview` | ファイルの責務 | ファイル冒頭 |

### @param / @return（関数の契約）

```javascript
/**
 * メールを検索して一覧を返す
 * @param {string} query Gmail検索条件
 * @return {Array<object>} メール一覧
 */
function searchMails(query) {}
```

関数の**契約書**と考えると分かりやすい。

### @type（この変数は何か？）

```javascript
/** @type {string} */
const SPREADSHEET_ID = "xxxx";
```

「これは文字列IDだよ」と宣言する役目。GASのゆるい型で事故を防ぐ。

### @typedef（オブジェクトの設計図）

```javascript
/**
 * メールレポート設定
 * @typedef {Object} MailReportSetting
 * @property {string} condition Gmail検索条件
 * @property {string} outputSheetName 出力先シート名
 * @property {number=} max 最大取得件数（省略可）
 * @property {string} parserType パーサー種別
 */

/** @type {MailReportSetting} */
const setting = {
  condition: 'subject:"完了"',
  outputSheetName: '一覧',
  max: 50,
  parserType: 'keyValue'
};
```

**@typedef は型を作る側**、@param はそれを使う側。

### @property と @param の違い

| タグ | 主語 | 役割 |
|------|------|------|
| `@property` | オブジェクト | 中身の説明 |
| `@param` | 関数 | 引数の説明 |

→ **データ構造 vs 関数契約** の違い。

### @fileoverview（このファイルは何をする？）

```javascript
/**
 * @fileoverview メールレポート設定を管理する
 */
```

複数ファイル構成のGASでは、役割の境界が見えにくいのでここが効く。

### 実務ルール

1. JSDocは**直後の要素1つにだけ対応**させる
2. 型は厳密より**構造が分かることを優先**
3. 運用メモは `// TODO:` に分離
4. 迷ったら「未来の自分が読めるか」で判断

### 最低限テンプレ（コピペ用）

```javascript
/**
 * @fileoverview 〇〇管理
 */

/**
 * @typedef {Object} Data
 * @property {string} id
 */

/** @type {string} */
const ID = 'xxx';

/**
 * @param {Data} data
 * @return {boolean}
 */
function run(data) {}
```

## 第3章：JavaScript と Python の対応比較

### 基本思想

| 観点 | JavaScript | Python |
|------|-----------|--------|
| 設計コメント | JSDoc | docstring |
| 型 | 任意 | 標準 |
| 設計文化 | 後付け | 前提 |

### コメント・仕様記述

| 目的 | JavaScript | Python |
|------|-----------|--------|
| 関数説明 | `/** */` | `""" """` |
| 引数 | `@param` | 型ヒント |
| 戻り値 | `@returns` | `-> type` |

### HTMLドキュメント生成ツール

| 観点 | JavaScript | Python |
|------|-----------|--------|
| 公式ツール | JSDoc | Sphinx |
| 入力 | JSDocコメント | docstring + 型 |
| 出力 | HTML | HTML |
| 自動化 | ◎ | ◎ |

### HTML生成コマンド

**JavaScript**

```bash
npm install -D jsdoc
npx jsdoc -c jsdoc.json
```

**Python**

```bash
pip install sphinx
sphinx-quickstart
sphinx-build -b html source docs
```

**GAS（Node.js側で実行）**

```bash
npx jsdoc src/gas -d docs
```

## 第4章：GitHub Actions で自動ドキュメント生成

### なぜ GitHub Actions と相性がいいのか

1. CLI一発でHTML生成できる
2. 出力が静的HTML
3. Node / Python が標準で使える

→ CI/CD 向きの条件を最初から満たしている。**「コメントを書く＝ドキュメントが勝手に更新される」** 状態を作れる。

### JavaScript（JSDoc）の構成例

**リポジトリ構成**

```
.
├ src/
│ └ index.js
├ jsdoc.json
├ package.json
└ .github/
  └ workflows/
    └ docs.yml
```

**GitHub Actions（最小構成）**

```yaml
name: Generate JSDoc

on:
  push:
    branches: [ main ]

jobs:
  docs:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: npm ci
      - run: npx jsdoc -c jsdoc.json
      - name: Deploy to GitHub Pages
        uses: peaceiris/actions-gh-pages@v4
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./docs
```

### Python（Sphinx）の構成例

**リポジトリ構成**

```
.
├ src/
│ └ app/
│   └ service.py
├ docs/
│ ├ source/
│ └ Makefile
└ .github/
  └ workflows/
    └ docs.yml
```

**GitHub Actions（最小構成）**

```yaml
name: Build Sphinx Docs

on:
  push:
    branches: [ main ]

jobs:
  docs:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.11"
      - run: pip install sphinx
      - run: sphinx-build -b html docs/source docs/build
      - name: Deploy to GitHub Pages
        uses: peaceiris/actions-gh-pages@v4
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./docs/build
```

### 実務的な運用パターン

| パターン | 内容 |
|---------|------|
| push時 | 常に最新ドキュメント |
| mainのみ | 安定版のみ生成 |
| 手動実行 | `workflow_dispatch` |
| PR時 | 差分レビュー用 |
